# 流式渲染与发布验证优化计划

> 使用 superpowers:executing-plans 按任务执行；先补行为回归再实现。用户已授权按审查结论自主优化，改动保留在工作区供审阅，不推送或发布。

**Goal:** 减少长会话流式输出中的全量克隆、重复 Markdown 解析与 DOM 重建，整理宿主入口并补齐本机验证。

**Architecture:** SessionStore 同步归并事件，允许订阅方声明关注字段，并提供不读取快照的变更通知。侧栏只在可见时按 16ms 合并快照，ready/重新显示恢复最新状态。聊天渲染按当前会话与消息位置缓存节点及内容签名，工具按 ID 复用；变更内容仍经过现有 Markdown 清洗。

**Tech Stack:** TypeScript strict、原生 DOM、Web Awesome、Vitest、现有 Playwright Core 与 VS Code 测试宿主，不引入新运行时依赖。

**Spec:** 本次会话中已核实的审查结论；README.md、AGENTS.md 的协议与界面约束。

## 设计取舍

- 采用界面发送合并与节点复用；不延迟业务订阅，不改 PI 的 RPC 协议。
- 不全面改写为不可变状态、差量传输或列表虚拟化，先移除已确认的重复工作。
- 使用逐项内容签名识别跨 Webview 快照的变化，避免依赖 PI 没有提供的稳定消息 ID。
- 按职责提取动作处理与连接初始化，保留集中服务装配，不为每个命令创建文件。
- 保留插件版本 1.0.0 与 PI 验证基线 1.5.2；类型仅对齐声明的 VS Code 最低版本。

## Review Focus

- 高频 delta 不触发队列与通知的整包克隆；agent_start/agent_settled 和队列控制仍同步可见。
- 隐藏、销毁、重新显示和 ready 不发送旧快照，不遗留定时器。
- 搜索、切换会话、分叉、权威 message_end 与工具结果更新不复用错误内容。
