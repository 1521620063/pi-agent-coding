# PI 插件 P0 / P1 / P2 实施计划

**Goal:** 按用户已确认的功能清单补齐输入、文件、会话与 RPC 快捷操作。

**Architecture:** 保持原生 TypeScript / DOM / Web Awesome。宿主服务处理工作区文件与 VS Code API，Webview 只通过严格校验的 action 通信；推理、会话和命令仍使用 PI 1.5.2 RPC。

**Tech Stack:** TypeScript strict、VS Code API、Web Awesome、Vitest、Playwright。

**Spec:** 用户已确认的上一轮 P0/P1/P2 功能表（17 项）；不包含另行评估的规划、审批、子智能体、MCP 管理或文件回滚。

## 约束与决定

- 保留之前自动连接改动，不提交、推送或发布；当前分支保留原工作区全部修改。
- 文件搜索只枚举路径；用户选择后才读取内容。读取和定位检查工作区、受信任状态、URI、真实路径及符号链接，不开放任意宿主文件访问。
- @ 候选使用宿主生成的短期 ID，不让 Webview 指定任意路径读取。候选分工作区 / 已打开 / 当前文件，支持未保存文档。
- 文件引用由宿主检查后定位；代码块中的任意文本不自动执行。代码复制与打开未保存文档由明确点击触发。
- 输入历史仅保存有限输入文本，不重放请求。候选、IME、Shift+Enter、草稿恢复及编辑器 revision 去重优先于历史与快捷输入。
- 恢复会话仅通过当前工作区索引及 PI switch_session；失败保留可用连接并报告，不自动重发消息。
- 变更导航列出 PI 工具报告触及的路径，SCM 对比由 VS Code 提供，不声称完整 diff、审批或回滚。
- Browser plugin 不可用，使用仓库已有 playwright-core 检查浏览器夹具，不新增依赖。
